OVERVIEW
----------------------------------------------------------------
A real-time dashboard to compare AI model inference performance
(latency + accuracy) in a live 5G O-RAN scenario.
Compares FastInfer (XGBoost) vs CNN (tractor-mono) on 4 traffic
types: VR, Haptic, Social, IoT.

COMPONENT 1: universal_agent.py + Dockerfile
----------------------------------------------------------------
Location : xChain/src/2026-netsoft-demo/api/container_cmd/
Image    : universal-agent (new Docker image)

3 modes via AGENT_MODE env var:

  AGENT_MODE=exec
    - On START:{cmd}  → run cmd as subprocess
    - On STOP         → kill subprocess
    - Used in         : oai-traffic-server sidecar

  AGENT_MODE=file
    - On START:{payload} → write payload to AGENT_OUTPUT_FILE
    - On STOP            → clear AGENT_OUTPUT_FILE
    - Used in            : xchain-smartgw-demo sidecar

  AGENT_MODE=log_collector
    - Tails LOG_FILE (shared emptyDir with main container)
    - Parses log lines using model-specific regex
    - Reads current_experiment.txt from RESULTS_DIR for ground truth
    - Resets counters when experiment changes
    - Writes accuracy/latency CSVs to RESULTS_DIR/{traffic_type}/
    - Used in: xchain-fastinfer sidecar, tractor-mono sidecar

Common env vars (all modes):
  DEMO_SERVER_HOST   # K8s service name of xchain-gui-server
  DEMO_SERVER_PORT   # default: 4000
  AGENT_MODE         # exec | file | log_collector

file mode extra:
  AGENT_OUTPUT_FILE  # default: /tmp/selected_models.txt

log_collector mode extra:
  MODEL_NAME         # fastinfer | cnn
  MODEL_TYPE         # xgboost | cnn  (selects log parser)
  LOG_FILE           # /model-logs/model.log (shared emptyDir)
  RESULTS_DIR        # /results (PVC mount)

Log parsers (from existing parse_logs.py):
  xgboost: single-line regex
    pattern: timestamp INFO UE=X -> Predicted class: Y | Latency=Xms | End2end=Xms
  cnn: two-line pair
    line1: timestamp INFO [UE=X] Predicted class: Y
    line2: timestamp INFO [BATCH KPM ...] ... end2end=X ms

Agent connection protocol:
  - Connects to DEMO_SERVER_HOST:DEMO_SERVER_PORT via TCP
  - Sends socket.gethostname() on connect (server matches by hostname)
  - Sends keep-alive "1" every 5 seconds
  - Auto-reconnects on disconnect
